# 项目约束

> 本文件是 Rough PPT Add-in 的硬约束。任何代码、UI、协议、安装包或验证改动前都必须先阅读本文件。
> 若与临时想法冲突，以本文件和冻结协议为准。

## 0. 修改前强制检查

1. 先读本文件。
2. 再读 `docs/target-mode-plan.md` 的活跃队列和冻结协议。
3. 涉及外部连接时，只读核对：
   - `D:\GitRepo\MCP\zlk-cluster-orchestrator`
   - `D:\GitRepo\my_img_manager`
4. 先看本仓 `git status --short --branch` 与最近提交；禁止覆盖用户未提交改动。
5. 禁止启用、恢复或模拟多角色/多智能体后台流程。单线程执行，直接改代码、验证、提交。

## 1. 产品边界

- 本项目是 Windows PowerPoint VSTO 插件，不是 Web 演示、不是 SVG 编辑器、不是通用图片导出工具。
- 核心能力：
  - Rough 手绘风格原生图形
  - ZLK 集群实验结果自动绘图
  - Zotero 论文图像/配色库
  - 用户素材库、配色库、论文图预设、特征块
- Rough 原生图形和 ZLK 图表最终对象必须是 PowerPoint 原生可编辑对象：`Shape` / `Freeform` / `Group` / `Line` / `Textbox` / `Table`。
- 禁止把 PNG、SVG、Canvas 截图、外部图片作为 Rough 图形或 ZLK 自动绘图链路的最终对象。
- 允许两个相互隔离的外部图像例外：Zotero 论文参考图像；用户显式选择并由独立科研 SVG 导入链路校验的本地 SVG。科研网站入口只允许固定白名单，但插件不根据文件来源声明真实性。例外不得扩展到 Rough 或 ZLK 自动绘图。
- 科研 SVG 必须限制文件体积，拒绝脚本、事件处理器、外部 URL、外部资源和危险 XML；网页预览与 PPT 插入必须使用同一份校验后 SVG 内容。
- 科研 SVG 直接插入只支持 PowerPoint 2016 及更高版本；PowerPoint 2013 保留旧任务窗格的原生科研绘图入口。

## 2. 视觉与交互硬约束

- 手绘视觉以 Rough.js / Excalidraw 风格为参考，但不得完整嵌入 Excalidraw 运行时。
- 插入后对象必须支持 PPT 原生拖动、对齐、缩放、旋转、复制、层级调整。
- 填充必须以手绘内层边界为准完整覆盖；外层扰动线不参与原生填充语义。
- 风格参数修改后，选区重绘必须实时生效；禁止“只改面板不改对象”的假控件。
- UI 中文为主。所有非 PPT 原生、意义不明确的按钮、标题、徽标、状态都必须有悬浮说明。
- Ribbon 放高频入口；右侧任务窗格保留完整参数、素材/配色管理和兜底操作。
- 右侧任务窗格的命令、导航和状态操作使用纯文字，不显示功能图标；仅原生形状预览、素材/论文图缩略图、配色色块和状态标记保留视觉内容。
- 危险操作必须页面内确认，禁止系统弹窗阻塞 PowerPoint。
- 定位类入口只定位，不直接执行删除、分享、导入、重绘、转换等危险或高代价动作。

## 3. 外部协议冻结

### 3.1 ZLK Cluster

- discovery：`%LOCALAPPDATA%\\RoughPptAddin\\automation.json`、`automation.token`
- 仅监听 `127.0.0.1` / `localhost`
- endpoint：`GET /health`、`POST /api/zlk-cluster/plot`
- token header：`Authorization: Bearer`、`X-Rough-Ppt-Token`、`X-RoughPpt-Automation-Token`
- `schemaVersion=1`；未知字段忽略，只接受 additive extensions
- 不得关闭已有 PPT，不得退出 PowerPoint
- 结果必须经 `zlk-cluster-result-importer.mjs` 归一化后再绘制
- 默认优先 `statistics.json` / 论文表格 CSV；禁止默认扫 raw dataset、checkpoint、Agent 全局态

### 3.2 Zotero Image Saver

- PPT 只读外部 SQLite，不读 `zotero.sqlite`
- 唯一共享库固定为 `%LOCALAPPDATA%\ZLK\paper-image-library\paper_images.sqlite`；`library.json` 只能确认该路径，任何自定义路径均回落固定路径
- bridge 可选；bridge 失败时白名单 `zotero://` fallback
- `Requested Zotero URI invalid` 时禁止 ShellExecute，只复制溯源 ID
- Zotero 关闭时仍可预览、搜索、取色、插图
- 完整图库界面由 Zotero 唯一维护。PPT 的“打开论文图片库”必须复用 Zotero 生成的 `paper-image-library.html`，不得复制或重实现图库卡片、表格、筛选、排序、高清查看、刷新、批量、分享、导入和删除界面；任务窗格只保留轻量 SQLite 快速预览、取色和插图。
- Zotero 运行且 bridge 就绪时，PPT 先发送仅用于界面刷新的 `refreshLibrary`，再打开系统临时目录下的 `pdf-image-saver\paper-image-library-view\paper-image-library.html`。PPT 不得发送 `deleteImages`、`exportImages`、`importImages`，不得把临时页面或图片文件作为长期数据源。

## 4. 资源、性能与安全

- 任务窗格大列表必须渐进渲染，禁止一次渲染大量缩略图/卡片。
- 搜索输入必须帧合并；键盘定位前必须 flush。
- 网络/DB 请求必须单飞或队列，防止旧响应覆盖新结果。
- ZLK 导入与自动绘图必须有文件数、单文件大小、总字节上限。
- 自动绘图并发必须门禁；忙碌时快速中文错误返回，不得阻塞 UI。
- 删除、导入、导出、分享必须有明确选择范围和失败反馈。
- 安装包必须支持覆盖安装；端用户安装路径不得依赖 Visual Studio Build Tools。

## 5. 修改纪律

- 优先扩展现有模块，不重写整条链路。
- 外部仓只读，不修改、不追随未冻结协议。
- 发现故障先写入 `docs/target-mode-plan.md` 或验证清单，再修代码。
- 防震荡：修 bug1 后同步验证相邻旧合同；若 bug 来回抖动，先抽共同根因和共享测试。
- 每个小批次只做一个同风险面改动并独立提交；单个小批次不运行测试、构建或打包。
- 每完成连续 5 个小批次，统一运行完整 `npm test` 和 UI 构建；全部通过后再统一打包，供用户手动安装检查。
- 五批次统一验证失败时先修复并重新完整验证，禁止产出或交付已知失败的安装包；Codex 不自动安装，也不关闭或重启 PowerPoint。
- `docs/manual-cleanup-candidates.md` 只记录需要完整删除的文件或目录。保留文件内的过期行、段落、函数、类、配置项或其他局部内容由 Codex 直接删除或修改，不需要人工确认，但不得把文件清空或替换为空壳，修改后必须保持文件完整可用。
- 提交信息只描述已验证能力，不写未验证承诺。

### 5.2 目标计划维护

- `docs/target-mode-plan.md` 只保留当前约束、冻结协议、验证基线、活跃队列和少量历史锚点。
- 每 5 个批次，或该文件明显变长时，必须压缩一次历史流水。
- 详细过程只进 git 提交，不在目标计划重复堆叠。

### 5.1 优化优先级

- 当前阶段优先优化 UI：外观、布局、发现性、首屏密度、图标一致性、状态可读性。
- 只有当 UI 已无明显可验证收益，或出现阻塞/危险操作/外部兼容断裂时，才优先进入功能层改动。
- UI 批次也必须保持：中文为主、tooltip、危险操作不直接执行、不引入 sticky/fixed 遮挡滚动内容。

## 6. 仍需优化的功能与方向

### 6.1 UI 布局与发现性

现状问题：

- 首屏信息密度高，新用户仍可能找不到重绘、配色、科研绘图入口。
- 形状下拉、快速插入、功能图标风格虽已统一，但仍需持续核对与原生习惯的一致性。

优化方向：

- 保持插件整体“插入 / 重绘 / 风格 / 数据”主路径；插入和重绘由 Ribbon 执行，右侧简洁模式只显示当前选区状态或单个参数/数据工作区。
- 继续压缩状态条、连接条、搜索提示的垂直占位。
- Ribbon 图标保持统一线性风格；任务窗格命令保持纯文字，形状预览继续复用本地形状图标。
- 在 UI 仍有明显改进空间时，批次默认优先做 UI，不穿插大功能开发。

### 6.2 风格参数与重绘一致性

现状问题：

- 参数很多，模板与手动参数容易互相覆盖认知。
- 历史版本中出现过“改参数不生效 / 强制回弹 / 只改载体不改边缘”。

优化方向：

- 参数变更即清空模板选中态；模板应用才回写整组参数。
- 重绘选区固定为“删除旧对象并在同位置按新参数重建”。
- 任何新增风格控件都必须接入实时同步与重绘链路，并补动作接线验证。

### 6.3 手绘填充与边缘

现状问题：

- 多层边界下，填充与最外层视觉边界必须严格对齐。
- 复杂形状曾出现错误连线、过度扭曲、笔画过密/过稀。

优化方向：

- 继续坚持“内层边界决定填充，外层只做视觉扰动”。
- 可保留涂刷填充作为可选模式，但不得破坏完整覆盖。
- 形状生成参数以“边界轻微扰动、主体几何稳定、速度快”为默认。

### 6.4 特征块与 3D

现状问题：

- 2D 网格较稳定；3D 透视、层序、间距 0、圆角闭合仍是高风险区。
- 手绘模式下每个独立方块都需要单独处理，间距 0 时要避免重合边重复描边变粗。

优化方向：

- 3D 以“可视面置顶、层序稳定、默认可读”为验收线，不再追求复杂圆角堆叠。
- 2D/3D 默认参数保持可保存；改参数后重绘必须直接更新选区，不新建幽灵对象。

### 6.5 配色库与素材库

现状问题：

- 配色来源多：Zotero、剪贴板、当前页、PPT 主题、用户保存包。
- 一键替换若只用部分颜色，会造成整体色板失衡。
- 素材/配色分享需要跨文件、可选择、可导入、体积可控。

优化方向：

- 整体替换必须支持布局预览，由用户选择最满意的映射。
- 分享包继续用安全 zip，限制体积与路径穿越。
- 删除/重命名统一页面内确认，避免误触。

### 6.6 外部兼容与资源占用

现状问题：

- ZLK / Zotero 外部仓持续演进，细粒度 UI 命名变化容易触发误报或真实漂移。
- 论文图像与配色刷新若重复读库，会放大卡顿。

优化方向：

- 兼容验证守语义与冻结协议，不锁死外部仓内部函数名。
- 列表、搜索、DB、自动绘图继续单飞、上限、渐进渲染。
- 连接状态看板只展示与定位，不执行危险操作。

### 6.7 安装与版本可辨认

现状问题：

- 用户反馈“装了没变化”时，常见根因是旧包残留、版本不可辨、PowerPoint 未加载新 DLL。

优化方向：

- 保持 MSI 覆盖安装与 `installerProductVersion` 可追踪。
- 任务窗格保留构建信息入口，便于核对 commit 与 dirty 状态。
- 未明确要求时不打包；明确要求时必须全量测试后再出 ZIP/MSI/EXE。

## 7. 禁止事项

- 禁止把图片/SVG 当作 Rough 或 ZLK 自动绘图最终对象；仅保留第 1 节定义的独立科研 SVG 导入例外。
- 禁止读取 Zotero 内部 `zotero.sqlite`。
- 禁止修改外部仓来“顺便修兼容”。
- 禁止关闭或重启用户的 PowerPoint / VS Code，除非用户明确要求。
- 禁止引入新的多角色后台智能体编排、角色扮演式实现流程、无人值守互相评审环。
- 禁止为了提速跳过与改动面相关的验证。
- 禁止扩大 Zotero 参考图像与独立科研 SVG 导入的例外范围。

## 8. 最小验收清单

改动合并前至少确认：

1. 是否仍满足原生可编辑对象约束。
2. 是否破坏 ZLK / Zotero 冻结协议。
3. 是否引入重复渲染、重复读库、阻塞 UI 的请求。
4. 是否存在假按钮、无 tooltip、英文主文案。
5. 是否对危险操作保留确认与中文错误。
6. 是否处于五批次统一验证节点；未到节点不得把尚未统一验证的能力写成已验证。
